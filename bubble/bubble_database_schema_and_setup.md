## 1. Database Schema Design (Data Types & Fields)

Bubble models data through relational Data Types. Set up the following in **Data** -> **Data Types**:

### 1.1 `User` (Built-in Data Type)
| Field Name | Field Type | Description |
| :--- | :--- | :--- |
| `email` | text (built-in) | User email address |
| `role` | Option Set (`User_Role`) | `"Admin"` or `"Author"` |
| `linked_author` | `Author` | Relationship to Author entity (null for Admins) |

### 1.2 `Author` Data Type
| Field Name | Field Type | Description |
| :--- | :--- | :--- |
| `author_id` | text | Unique ID (e.g. `AUTH001`) |
| `name` | text | Author's full name (e.g. `"Priya Sharma"`) |
| `email` | text | Author's email address |
| `phone` | text | Contact phone number |
| `city` | text | City (e.g. `"Mumbai"`, `"Delhi"`, `"Bangalore"`) |
| `joined_date` | date | Author onboarding date |
| `books` | List of `Book`s | List of books authored |
| `total_royalty_earned` | number | Pre-aggregated sum of all royalty earned (₹) |
| `total_royalty_paid` | number | Pre-aggregated sum of royalty paid out (₹) |
| `total_royalty_pending` | number | Current outstanding balance (₹) |
| `payout_status` | Option Set (`Payout_Status`) | `"Fully Paid"`, `"Pending"`, or `"Overdue"` |

### 1.3 `Book` Data Type
| Field Name | Field Type | Description |
| :--- | :--- | :--- |
| `book_id` | text | Unique ID (e.g. `BK001`) |
| `title` | text | Title of the book |
| `isbn` | text | ISBN string (e.g. `978-93-5XXXX-01-1`) |
| `genre` | text | Book genre |
| `publication_date` | date | Publication date (null if in production) |
| `status` | text | e.g. `"Published & Live"`, `"In Production - Cover Design"` |
| `mrp` | number | Retail price in INR (null if in production) |
| `author_royalty_per_copy`| number | Author royalty per copy (INR) |
| `total_copies_sold` | number | Total units sold across all channels |
| `total_royalty_earned` | number | Total royalty earned (INR) |
| `royalty_paid` | number | Total royalty paid out (INR) |
| `royalty_pending` | number | Royalty pending payout (INR) |
| `last_royalty_payout_date` | date | Date of most recent payout |
| `print_partner` | text | `"In-House"`, `"Repro India"`, or `"Epitome Books"` |
| `available_on` | List of texts | `["Amazon India", "Flipkart", "BookLeaf Store"]` |
| `author` | `Author` | Parent Author reference |
| `royalty_badge` | Option Set (`Royalty_Badge`) | `"Green"`, `"Yellow"`, `"Red"`, or `"In Production"` |

### 1.4 `Notification_Log` Data Type
| Field Name | Field Type | Description |
| :--- | :--- | :--- |
| `author` | `Author` | Author recipient reference |
| `author_name` | text | Author name (for fast UI rendering) |
| `author_email` | text | Author email address |
| `sent_at` | date | Timestamp of notification dispatch |
| `status` | text / Option Set | `"Success"` or `"Failed"` |
| `email_subject` | text | Generated subject line |
| `email_body` | text | Complete HTML / text email generated by AI |
| `trigger_type` | text | `"Single Manual"` or `"Bulk Admin"` |
| `error_message` | text | Reason if status is Failed |

## 2. Option Sets (Enums)

Go to **Data** -> **Option Sets** and define:

1. **`Payout_Status`**:
   - `Fully Paid` (Display: "Fully Paid")
   - `Pending` (Display: "Pending")
   - `Overdue` (Display: "Overdue")

2. **`Royalty_Badge`**:
   - `Green` (Attributes: color = `#10B981`, label = "Fully Settled")
   - `Yellow` (Attributes: color = `#F59E0B`, label = "Pending (In Cycle)")
   - `Red` (Attributes: color = `#EF4444`, label = "Overdue (>90 Days)")
   - `In_Production` (Attributes: color = `#6B7280`, label = "In Production")

3. **`User_Role`**:
   - `Admin`
   - `Author`

## 3. Privacy Rules (Data Isolation)

In **Data** -> **Privacy**:

### 3.1 `Book` Privacy Rules
- **Rule 1 — Admin Full Access:**
  - `Current User's role is "Admin"` → Find in searches [✓], View all fields [✓]
- **Rule 2 — Author Self Access:**
  - `Current User's linked_author is This Book's author` → Find in searches [✓], View all fields [✓]
- **Everyone Else (Default):**
  - Find in searches [✗], View all fields [✗]

### 3.2 `Author` Privacy Rules
- **Rule 1 — Admin Full Access:**
  - `Current User's role is "Admin"` → Find in searches [✓], View all fields [✓]
- **Rule 2 — Author Self Profile:**
  - `Current User's linked_author is This Author` → Find in searches [✓], View all fields [✓]
- **Everyone Else:**
  - Find in searches [✗], View all fields [✗]

### 3.3 `Notification_Log` Privacy Rules
- **Rule 1 — Admin Access:** `Current User's role is "Admin"` → Full access [✓]
- **Rule 2 — Author Access:** `Current User's linked_author is This Notification_Log's author` → View only [✓]

## 4. API Connector Setup (Bubble ↔ n8n Webhook)

Install the **API Connector** plugin from the Bubble plugin marketplace:

1. **API Name:** `n8n Automation`
2. **Authentication:** `None or self-handled`
3. **Default Headers:**
   - `x-bookleaf-api-key`: `bookleaf_secure_token_2026`
   - `Content-Type`: `application/json`
4. **Call Name:** `Trigger Royalty Summary`
   - **Use as:** `Action`
   - **Data type:** `JSON`
   - **Method:** `POST`
   - **URL:** `https://<your-n8n-instance>/webhook/bookleaf-royalty-summary`
   - **Body (JSON):**
     ```json
     {
       "author_id": "<author_id>",
       "name": "<name>",
       "email": "<email>",
       "city": "<city>",
       "books": [
         {
           "title": "<title>",
           "isbn": "<isbn>",
           "status": "<status>",
           "mrp": 399,
           "total_copies_sold": 100,
           "total_royalty_earned": 3500,
           "royalty_paid": 2000,
           "royalty_pending": 1500,
           "last_royalty_payout_date": "2025-10-15"
         }
       ]
     }
     ```
   - Uncheck `Private` for the dynamic parameters (`<author_id>`, `<name>`, etc.) so workflows can inject current author data dynamically.

## 5. Front-End Pages & Workflows

### 5.1 Author Dashboard (`author_dashboard`)
- **Header:** Welcome `[Current User's linked_author's name]`, Logout button.
- **Consolidated KPI Cards:**
  - Total Royalty Earned: `Current User's linked_author's books's total_royalty_earned:sum:formatted as Currency (₹)`
  - Total Royalty Paid: `Current User's linked_author's books's royalty_paid:sum:formatted as Currency (₹)`
  - Total Pending Balance: `Current User's linked_author's books's royalty_pending:sum:formatted as Currency (₹)`
- **My Books Repeating Group:**
  - Source: `Search for Books where author = Current User's linked_author`
  - Columns: Title, ISBN, Genre, Status, MRP, Copies Sold, Royalty Earned, Royalty Paid, Pending, Last Payout Date, Status Badge.
  - **Badge Conditionals:**
    - If `This Book's royalty_badge is "Green"` → Green badge ("Settled").
    - If `This Book's royalty_badge is "Yellow"` → Yellow badge ("In Cycle").
    - If `This Book's royalty_badge is "Red"` → Red badge ("Overdue").
    - If `This Book's status contains "In Production"` → Gray badge ("In Production").

### 5.2 Admin Operations Dashboard (`admin_dashboard`)
- **Filters Toolbar:**
  - Search Input: Author name search filter.
  - City Dropdown: `"All Cities"`, `"Mumbai"`, `"Delhi"`, `"Bangalore"`, etc.
  - Payout Status Dropdown: `"All Statuses"`, `"Fully Paid"`, `"Pending"`, `"Overdue"`.
  - Button: **"⚡ Bulk Trigger: Send Pending Summaries"** (runs API call for all authors with `total_royalty_pending > 0`).
- **Authors Repeating Group:**
  - Displays all authors filtered by City, Status, and Search Name.
  - Columns: Author ID, Name, Email, City, Total Books, Total Earned, Total Pending, Status Badge, **"View Details"** button.
- **Author Detail Modal / Slide-out:**
  - Full author breakdown with their list of books.
  - Primary Button: **"✉️ Generate & Send Royalty Summary"**
    - Workflow:
      1. Trigger API Connector call: `n8n Automation - Trigger Royalty Summary`.
      2. Create a new `Notification_Log` record in Bubble with status `"Success"`.
      3. Display notification toast: *"Royalty summary email generated and sent!"*.
- **Notification Log Table:**
  - Repeating group showing `Notification_Log` sorted by `sent_at` descending.
  - Columns: Author Name, Sent At, Status badge (`Success` / `Failed`), and **"View Email"** button opening the AI HTML body preview.

## 6. Importing the Dataset into Bubble

Pre-formatted CSV files are ready in `bubble/`:
- `authors.csv`: 10 authors with pre-aggregated earnings and payout status.
- `books.csv`: 18 books with all financial figures, payout dates, and status badges.

In Bubble:
1. Go to **Data** -> **App Data**.
2. Select **Author** -> click **Upload** -> select `authors.csv` -> Map fields -> Confirm.
3. Select **Book** -> click **Upload** -> select `books.csv` -> Map fields -> Confirm.
